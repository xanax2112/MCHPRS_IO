# 文件格式：`io.txt` 与存储器文件

本文件是 MCHPRS_IO 从工作目录读取的两类文件的参考手册。报文协议见配套的 `protocol.md`。

| 文件 | 用途 | 谁生成 |
| --- | --- | --- |
| `io.txt` | 声明 IO 组：脚本可读写的、有名字的方块坐标集合 | 你 |
| `memory/*.rom.txt` | 只读存储器，从 Logisim 兼容的十六进制镜像载入 | 你（或 Logisim 导出） |
| `memory/*.ram.txt` | 可写存储器，服务器在事件点回写 | 你 |

两类文件共用同一套坐标与注释语法，并且都校验两次：**加载时**一次，**编译成功后**再一次（只有编译后才知道某个坐标上究竟是哪种元件）。

## 1. 通用语法

### 1.1 编码与注释

- 文件为 UTF-8 文本。
- 注释：`// 行注释`、`# 行注释`、`/* 块注释 */`。
- 空行忽略。

### 1.2 键

```toml
origin = 0
clk = 12, 64, 12
width = 4
rs_width = 2
```

- 一行一个 `键 = 值`，`=` 两边空格随意。
- 键按名字匹配，且只在所属块内生效。

### 1.3 坐标列表

列表以 `[` 开始、`]` 结束，每个条目展开成一个或多个坐标。

| 写法 | 例子 | 含义 |
| --- | --- | --- |
| 单点 | `10, 64, 10` | 一个坐标 |
| 步进 | `10, 64, 10, +2x, 4` | 起点、方向、数量 |
| 矩阵 | `matrix: 10, 64, 10, +2x, 3, +4y, 5` | 3×5 的方块区域，行优先（详见 §4） |

步进规则：步长 1–255，数量 1–1024，方向只认 `x` / `y` / `z`，符号必填（`+` 或 `-`）。红石元件通常隔一格摆一个，所以坐标步长是 2；其它间距也可以。

### 1.4 `origin`

`origin` 用来整体位移一个块。只接受两种写法：

- `origin = 0` —— 不偏移；
- `origin = x, y, z` —— 绝对偏移，允许负数。

单个非零数字（例如 `origin = 5`）会报错，要么写 `0`，要么写三元组。

```toml
input switches = [
origin = 100, 64, -8
clk = 40, 64, 10        # 时钟实际位置：(140, 128, 2)
width = 2
0, 0, 0                 # 实际位置：(100, 64, -8)
2, 0, 0                 # 实际位置：(102, 64, -8)
]
```

`origin` 会加到该块的**所有**坐标上，包括 `clk`。`clk` 的规则一样：`0`（或加起来是 `0, 0, 0` 的三元组）表示无时钟；其它三元组是坐标，同样加 `origin`。

memory 文件在文件级使用同一个键：

```text
origin = 100, 64, -8
clk = 40, 64, 10

address coordinate = [
width = 2
0, 0, 0
2, 0, 0
]
```

## 2. `io.txt`

### 2.1 块

```toml
input switches = [
origin = 0
clk = 0
width = 2
10, 64, 10
10, 64, 12
]

output lamps = [
origin = 0
clk = 40, 64, 10
width = 2
20, 64, 10, +2x, 2
]
```

块头是 `<角色> <组名> = [`，块以 `]` 结束。

第一行可以写版本声明 `v<版本> hex words addressed`，**0.5.0 及以后**接受；低于 0.5.0 会禁用整个文件。不写版本行的文件照旧加载。

| 角色 | 方向 | 允许的元件 |
| --- | --- | --- |
| `input` | 脚本 → 电路 | 拉杆、压力板 |
| `output` | 电路 → 脚本 | 红石灯、活板门、音符盒 |
| `analog_input` | 脚本 → 电路 | 点状红石粉 |
| `analog_output` | 电路 → 脚本 | 点状红石粉，且不得被其它信号驱动 |

### 2.2 必填键

| 键 | 哪类块需要 | 含义 |
| --- | --- | --- |
| `origin` | 所有块 | 加到该块所有坐标上的偏移 |
| `clk` | 所有块 | 时钟元件，**必须是按钮**；`0` 表示无时钟 |
| `width` | 所有块 | 数电：点数；模电：总位数 |
| `rs_width` | 仅模电块 | 模电点数 |

数电组：`width` 等于展开后的坐标数。

模电组：**`rs_width` 与 `width` 都必须写**，顺序任意，写在坐标之前。
`rs_width` 必须等于坐标数，`width` 必须等于 `rs_width × 4`；对不上该组禁用。

### 2.3 组名

- `[A-Za-z0-9_]+`，大小写敏感。
- 整个文件内唯一，input、output、analog 之间一起查重。

### 2.4 校验

| 检查 | 时机 | 结果 |
| --- | --- | --- |
| 语法、块未闭合、块头非法 | 加载 | 整个 `io.txt` 禁用 |
| 缺键、`width` / `rs_width` 不符、宽度关系错、组名重复、时钟落在数据点上 | 加载 | 只禁用该块 |
| 坐标上没有元件 | 编译后 | 只禁用该块 |
| 元件类型不符（输入要拉杆/压力板，输出要灯/活板门/音符盒，时钟要按钮） | 编译后 | 只禁用该块 |
| `clk` 与别的 io 组相同 | 加载 | 后出现的块禁用 |
| `clk` 与 memory 的时钟相同 | 编译后 | 禁 io 块，memory 不受影响 |

报错信息里的行号一律按**整个文件**计。

### 2.5 时钟与运行行为

| 情形 | 行为 |
| --- | --- |
| 有 `clk` 的组收到 `INPUT` | 写入数据并在**同一 tick** 脉冲按钮一次 |
| 无 `clk` 的组收到 `INPUT` | 只写数据、不脉冲，不需要时钟 |
| 无 `clk` 的输出组 | 任一位变化就推 `OUTPUT` |
| 有 `clk` 的输出组 | 只在按钮上升沿推一次 |
| 重新编译 | 清空全部 `POUT` 绑定与预约 |

模电点只有让编译器保留下来才会出现在图里：点需要 `-d`（`--wire-dot-out`），十字需要 `-c`（`--wire-cross-out`）。缺了对应参数，该点会被报成缺元件，整组禁用。

### 2.6 示例

数电输入输出各一组：

```toml
input counter = [
origin = 0
clk = 30, 64, 10
width = 4
0, 64, 10
2, 64, 10
4, 64, 10
6, 64, 10
]

output display = [
origin = 0
clk = 0
width = 8
10, 64, 20, +2x, 8
]
```

两点模电总线（2 点 = 8 bit）：

```toml
analog_input bus = [
origin = 0
clk = 0
rs_width = 2
width = 8
40, 64, 0
42, 64, 0
]
```

矩阵输出，3 列 × 2 行（6 个灯）：

```toml
output grid = [
origin = 0
clk = 0
width = 6
matrix: 0, 64, 30, +2x, 3, +3z, 2
]
```

`matrix:` 形式接受 1–3 段 `步长轴, 数量`，按行优先展开；完整规则（段数限制、展开顺序、行内补零、hex 长度）见 §4。

## 3. 存储器文件

### 3.1 文件名与首行

- 只读：`memory/<名字>.rom.txt`；可写：`memory/<名字>.ram.txt`。
- 首行是版本声明，**0.5.0 及以后**的版本都接受；**只写版本号**（`v0.5.3-alpha`，服务器生成的 `io.txt` 就是这种）也可加载：

```text
v0.5.3-alpha hex words addressed
```

版本不符的文件在加载时被拒绝，只写日志说明原因。

文件名以点号开头的（`memory/.rom.txt`、`memory/.ram.txt`）是首次启动写下的骨架模板，加载器会跳过它们。

### 3.2 结构

```text
v0.5.3-alpha hex words addressed
origin = 0
clk = 0

address coordinate = [
width = 4
-8, 64, 0, +2x, 4
]

data coordinate = [
width = 8
2, 64, 0, +2x, 8
]

00: 0f 3c 69 00 00 00 00 00
```

- `origin` 与 `clk` 是文件级键；`origin` 加到所有端口坐标上，包括 `clk`。
- `clk = 0` 表示无时钟。**RAM 的 `clk` 必须指向真实方块**；ROM 可以无时钟（此时跟随地址变化）。
- 每个端口列表第一项必须是 `width = N`，展开后正好 N 个点。
- 数据段从第一行“看起来像数据”的行开始（`地址:` 或纯十六进制字）。

### 3.3 端口键

| 角色 | 数电键 | 模电键 | 方向 |
| --- | --- | --- | --- |
| 地址 | `address coordinate` | `analog address coordinate` | 输入 |
| 写数据 | `write data coordinate` | `analog write data coordinate` | 输入 |
| 读数据 | `read data coordinate` | `analog read data coordinate` | 输出 |
| ROM 数据 | `data coordinate` | `analog data coordinate` | 输出 |
| 写使能 | `write enable` | — | 输入 |
| 读使能 | `read enable` | — | 输入 |
| 字节写使能 | `byte write enable` | — | 输入 |

- `write enable` / `read enable` 是**单坐标**（`write enable = x, y, z`），**必须写**，不接受 `0`。
- `byte write enable` 是**列表**；写 `byte write enable = [ width = 0 ]` 表示**不使用字节写使能**（写使能只受 `we` 控制）；带坐标时条数必须等于 `ceil(数据位宽 / 8)`。
- 字节写使能**只在 `write enable = 1` 时生效**，与现实电路一致。
- 模电键名**用空格分隔，不带下划线**。
- 每个角色只能有一个列表；同一角色的数电键与模电键互斥。
- 数电/模电**按每条线选**，一个 memory 里可以混搭。
- 模电列表与 `io.txt` 一样要同时写 `rs_width`（点数）与 `width`（总位数 = 点数 × 4）。
- 地址位宽最大 63 位（模电按 `address coordinate` 的点数 × 4 计）。

### 3.4 数据段

```
00: 0f 3c 69 00 00 00 00 00
1f: 00 0a
```

- `<地址>:` 设定当前地址，后面的字依次写入。
- 没有冒号的行表示接着上一行继续写。
- 地址与字都是十六进制（可带 `0x` 前缀）。
- 字太短会在前端补零，太长只保留低位。
- `matrix` 端口的字先按行补零再打包。
- 没有数据的地址读作 0。

### 3.5 RAM 回写

RAM 运行期不写盘，只在下列时机落盘：

1. 任意玩家退出服务器；
2. 服务器退出（SIGINT / SIGTERM / SIGHUP；SIGKILL 不算）；
3. `/redpiler reset`；
4. 编译崩溃；
5. `/memory reload` 之前。

回写格式（Logisim 兼容）：

- 每行固定 8 个 word，行首地址按 8 对齐；
- 整块没有数据的块整块省略；
- 空格子按数据位宽补零；
- 地址按地址总线宽度补足位数；
- 首行版本号重写为当前内核版本；
- 文件原子替换（先写临时文件再 rename）。

### 3.6 校验

| 检查 | 时机 | 结果 |
| --- | --- | --- |
| 首行版本、语法、`width` 与坐标数、模电双键 | 加载 | 整文件禁用 |
| 端口坐标上没有元件、元件类型错 | 编译后 | 整文件禁用 |
| 同一存储器的两位落在同一坐标 | 加载 | 整文件禁用 |
| 数据点与地址 / 时钟 / 使能点相邻 | 加载 | 整文件禁用 |
| 读数据与写数据共用坐标 | 加载 | 整文件禁用 |

相邻判冲突的原因：写给数据总线的信号会直接驱动它本该读取的那条线。ROM 检查数据点对地址与时钟，RAM 检查读数据点对写数据、使能、时钟与地址。

编译后校验失败时，RAM 内存里未落盘的数据直接丢弃；被禁用的存储器永不回写。

### 3.7 示例

4 位地址、8 位数据的 ROM：

```text
v0.5.3-alpha hex words addressed
origin = 0
clk = 0

address coordinate = [
width = 4
-8, 64, 0, +2x, 4
]

data coordinate = [
width = 8
2, 64, 0, +2x, 8
]

00: 0f 3c 69 00
```

带时钟与使能的 RAM：

```text
v0.5.3-alpha hex words addressed
origin = 0
clk = 20, 64, 0

address coordinate = [
width = 4
-8, 64, 2, +2x, 4
]

write data coordinate = [
width = 8
2, 64, 2, +2x, 8
]

read data coordinate = [
width = 8
2, 64, 4, +2x, 8
]

write enable = -8, 64, 4
read enable = -8, 64, 6

00: 00
```

模电端口：

```text
analog address coordinate = [
rs_width = 2
width = 8
-8, 64, 0
-8, 64, 2
]

analog data coordinate = [
rs_width = 2
width = 8
2, 64, 0
4, 64, 0
]
```

## 4. `matrix:` 展开规则

```text
matrix: 10, 64, 10, +2x, 3, +4z, 5
```

- 前缀是 `matrix:`（单词不分大小写，冒号必须有），后面跟普通的起点 `x, y, z`。
- 起点之后必须是 **1 到 3 段** `方向, 数量`，因此整行按逗号切开后有 5、7 或 9 段。
- **只能写一行**：`matrix:` 列表跨行会报错（`a matrix: list must be a single line`）。
- **数电与模电都适用**：模电 `matrix:` **尚未实现**，当前版本会报 `a matrix: list cannot be analog`，已登记为台账 BUG-010。
- 方向写法：显式 `+` 或 `-`，数值 1–255，末尾是轴 `x` / `y` / `z`（轴字母不分大小写）。数值 0 报错。例：`+2x`、`-3y`、`+4z`、`+16y`。
- 数量写法：纯数字，1–1024。
- 展开是混合进制、**第一段变化最快**，等价于嵌套循环：

  ```text
  for i3 in 0..count3:      # 最慢
    for i2 in 0..count2:
      for i1 in 0..count1:  # 最快
        point = origin + step1*i1 + step2*i2 + step3*i3
  ```

- 同一根轴可以出现在多段里，位移会叠加。
- 总点数 = `count1 * count2 * count3`，必须等于声明的 `width`（点数）。
- 数电补零：`count1` 个点构成一行，每行在**前端补零**到整 4 bit；`rows = count2 * count3`。
- **红石屏幕（像素阵列）推荐使用 `matrix:`**：每一行对应一组十六进制位，打包结果按扫描线排列，而不是被拍平成一维点序。
- **matrix 组的 hex 长度与 `width` 不同**：协议按 `rows * ceil(count1 / 4)` 个十六进制位打包，因为每行各自带补零。补出来的位不占位号，`READ <name>:<bit>` 也寻址不到。
- memory 的 matrix 端口用同一套展开；数据字先按行补零再打包，读取时再去掉。
- 模电是**一个点位一个十六进制位**，所以模电 `matrix:` 组打包 `count1 × count2 × count3` 个十六进制位，行内不补零（每点本身已是 4 bit）。


块里声明的 `origin` 会加到该块的**所有**坐标上，包括 `clk`。

### 4.1 同一组点，两种写法

6 个灯，3 列 × 2 行，矩阵写法：

```toml
output grid = [
origin = 0
clk = 0
width = 6
matrix: 0, 64, 30, +2x, 3, +3z, 2
]
```

同样的 6 个坐标，普通写法：

```toml
output grid = [
origin = 0
clk = 0
width = 6
0, 64, 30, +2x, 3
0, 64, 33, +2x, 3
]
```

两种写法都声明 `width = 6`，但打包出来的 hex 并不相同。设六个点依次为
A=(0,64,30)、B=(2,64,30)、C=(4,64,30)、D=(0,64,33)、E=(2,64,33)、F=(4,64,33)，
要写入 A=1、B=0、C=1、D=1、E=0、F=1：

| | 矩阵写法 | 普通写法 |
| --- | --- | --- |
| 打包方式 | 每行前端补零：`0ABC` `0DEF` | 整个向量前端补零：`00ABCDEF` |
| 位串 | `0101` `0101` | `00101101` |
| hex | `55` | `2d` |
| 长度 | `rows × ceil(3/4)` = 2 位 | `ceil(6/4)` = 2 位 |

这个例子里两者都是 2 位，但数值不同，因为每一行的补零位夹在行与行之间。只要列数不是 4 的倍数，
长度也会不同：5 列 × 2 行（`width = 10`）矩阵写法是 4 位（`ceil(5/4) × 2`），普通写法只有 3 位
（`ceil(10/4)`）。

两种写法的点位顺序相同，所以 `READ <name>:<bit>`（`bit 0` = 最后一个点）寻址到的是同一个灯，
差别只在 hex 打包。

## 5. 限制与默认值

| 项 | 限制 / 默认 |
| --- | --- |
| 单行步进 | 步长 1–255，数量 1–1024 |
| 矩阵 | 1–3 段，只能单行，起点 + `±步长 轴, 数量`，数量 1–1024，步长 1–255 |
| 组名 | `[A-Za-z0-9_]+`，全局唯一，区分大小写 |
| 点宽 | 数电 1 bit，模电 4 bit（0–15） |
| 地址总线 | 最多 63 位 |
| `width = 0` | 允许：空列表（无坐标） |
| 存储器目录 | 与 `Config.toml` 同级的 `memory/` |
| 存储器后缀 | `.rom.txt`、`.ram.txt` |

## 6. 启动前检查清单

- [ ] 每个块都有 `origin`、`clk`、`width`
- [ ] 模电块同时有 `rs_width` 与 `width`，且 `width = rs_width × 4`
- [ ] 坐标数等于声明的位宽
- [ ] 组名不重复
- [ ] 时钟是按钮，且每个 io 组只出现一次
- [ ] memory 文件首行是 `v0.5.3-alpha hex words addressed`
- [ ] 模电电路会用 `-d` 编译（用到十字时还要 `-c`）
