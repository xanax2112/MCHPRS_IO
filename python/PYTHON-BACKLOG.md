### 1.1 电路测试分类

| 分类 | 含义 | 代表 |
| --- | --- | --- |
| 时序精确（无时钟 / 有时钟，同一规则） | 给定元件延迟；每组只允许 1 条 `OUTPUT`（多条=毛刺→失败）；`OUTPUT` tick 必须等于「输入生效 tick + 延迟 − 1」；该 tick 上的值正确即通过。有时钟组 `INPUT` 脉冲一次 `clk`，输出只在上升沿推送，判定不变 | xor（PY-002） |
| 流水时序精确 | 仅 `/tick seq`；给定输入间隔（≥2t）与输出延迟；连续灌入向量，判定相邻输出间隔 == 输入间隔且每个值正确 | 待定 |
| 无时序正确性 | 只写输入，等一段时间，中间 `OUTPUT` 全丢弃，`POUT` 查一次，值对即通过；**不判 tick** | xor（PY-003，示例） |

其余分类 ⏳ 待用户说明，未登记前不自行假设。

**PY-002 `xor.py`（🚧 已写码，未验收）**

- 需求（用户 2026-11-02 确认）：输入 8×2（16 位，高 8 位 | 低 8 位），输出 8 位；
  期望 `xor_out == 高 8 位 ^ 低 8 位`；**普通模式，`INPUT` 后等 `OUTPUT`**。
- 电路分类：**无时钟时序精确**（用户 2026-11-02 分类，见 §1.1）。
- 延迟（用户 2026-11-02 修正）：设计延迟 **1t**；按项目写法「真实延迟 = 输出采样 tick − 输入生效 tick + 1」，
  脚本应算出的延迟是 **0t**，即断言 `输出 tick − 输入 tick == 0`。**原先按 +1 写的断言已作废。**
- 判定（用户 2026-11-02 完整定义，覆盖此前所有写法）：
  - 给定元件**延迟**（tick），xor 为 1t；
  - 发 `INPUT`，记录**输入生效 tick**；
  - **每组只允许收到 1 条 `OUTPUT`**；收到多条 → 视为**毛刺**，该组失败；
  - `OUTPUT` 的 tick 必须等于正确延迟 tick（项目写法换算：`输出 tick = 输入 tick + 延迟 − 1`）；
  - 在该 tick 上检查值，等于 `A ^ B` → 通过。
- **有时钟组并入同一判定**（用户 2026-11-02 定）：`INPUT` 会脉冲一次 `clk`，输出组只在上升沿推送；
  延迟、毛刺、tick 规则与无时钟组完全一致，不另立条目。
- 参数（用户 2026-11-02：**全部写在代码配置区**，不走命令行）：`DELAY` 元件延迟（xor = 1）；
  `GLITCH_WAIT` 毛刺观测窗口；0 条 `OUTPUT` → 先用 `POUT` 确认再判。
- 热身（用户 2026-11-02 先要求、同日取消）：**已移除**，不做任何预热；首组若值未变化，走 `POUT` 确认分支。
- 实现：`timing.py`（旧 `xor.py` 已按用户 2026-11-02 指令删除，功能并入通用时序精确测试）。
- 实测（2026-11-02，`betterio = true`，rtps 5000）：**65535 通过 / 1 失败**，耗时 324.8s；
  65535 个有效样本的 tick 差**全为 0**（即项目写法的 1t）。
- 那 1 条失败已定性：`A=0x80 B=0x00`（期望 0x80），前一组 `A=0x7F B=0xFF` 输出也是 0x80
  → **值不变、无推送**，是遍历顺序造成的假失败，**不是服务器问题**。
- 修复：内层改蛇形遍历（相邻组只变一位，输出必变），**待重跑确认**。

**PY-003 无时序正确性测试（📝 已登记，待写码指令）**

- 用户 2026-11-02 定义：最简单的测试，**只验证结果是否正确，不验证时序**。
- 流程（以异或门为例）：
  1. 只发 `INPUT` 写入数据；
  2. 等待一段时间；
  3. 这期间服务器推送的 `OUTPUT` **全部丢弃**，不解析、不校验；
  4. 时间到后发一次 `POUT` 查询；
  5. 取回的值与期望一致 → 通过，否则失败。
- 不判 tick、不依赖推送内容、不要求固定延迟。
- 参数（用户 2026-11-02：**全部写在代码配置区**）：等待时长为配置区常量；覆盖分三种——**全量 / 随机 / 指定**，配置区选择；
  `POUT` 前**先读空管道**；值不对**直接记失败**，不重试。
- 状态：**已登记，等用户说“写代码”**。
